# PRD: Cycling Route Finder「ちょいチャリ」

作成: PdM / 2026-10-04 / v1

## 1. 背景と目的
- ユーザーはサイクリングを「運動として習慣化」したい。
- 最大の障壁は **「どこに行くか決めるのが面倒」**。
- このアプリは「時間を選ぶ → ワクワクする候補が並ぶ → タップ → Googleマップでナビ開始」までを **最短 3タップ / 10秒** で完結させる。

## 2. ターゲット / ペルソナ
- 平日夕方や休日の隙間時間（15分〜1.5時間）に軽く走りたい社会人。
- ロードバイク〜クロスバイク〜ママチャリまで。速度の個人差あり。
- その日の気分で「ガッツリ登りたい日」「平坦でのんびり流したい日」がある。

## 3. コア体験（Happy Path）
1. アプリを開く → 現在地を自動取得（許可がなければ地図で手動指定 / デモ地点）
2. 時間チップを選ぶ: 15分 / 30分 / 45分 / 1時間 / 1時間15分 / 1時間30分
3. 候補が写真付きカードで大量に並ぶ（目標 20〜40件）
4. 各カードに「片道距離・往復目安時間・高低差（獲得標高＋ラベル）・カテゴリ」
5. カードをタップ → 詳細（写真・標高プロファイル図）→「Googleマップで出発」
6. Googleマップ（自転車モード）が開き、即スタート

## 4. 機能要件
### MUST（v1）
- M1 時間選択（6種）。往復時間 T に対し片道到達距離を算出。
  - 片道距離 = 速度 × (T/2) ÷ 迂回係数(1.25〜1.3)。
  - 速度プリセット: のんびり 12km/h / ふつう 16km/h / 速め 20km/h（設定で変更、localStorage保存）
  - 候補は「目標距離の 60%〜100%」のドーナツ領域を中心に（近すぎる候補は運動にならない）。
- M2 現在地取得（Geolocation API）。不可ならデモ地点（東京駅）＋手動変更。
- M3 目的地候補の取得（Provider 抽象化）
  - OSM Overpass API（無料・キー不要）: 公園、展望台、カフェ、神社仏閣、川辺/海辺、史跡、ベーカリー等
  - Google Places API（`VITE_GOOGLE_MAPS_API_KEY` があれば利用、写真もGoogleから）
  - どちらも失敗したら **モックデータ** に自動フォールバック（UIに小さく「デモデータ」表示）
- M4 写真表示: Google Places Photo（キーあり時）→ OSMの wikimedia_commons / image / wikidata タグ → Wikipedia / Commons API → カテゴリ別の美しいフォールバック（グラデ＋イラスト/絵文字）
- M5 高低差: Open-Meteo Elevation API（無料・キー不要）で経路上をサンプリング
  - 経路は OSRM（bike）が取れればその形状、無理なら直線補間
  - 表示: 獲得標高(m)・最大勾配・ラベル（🟢フラット / 🟡ゆるアップダウン / 🔴ヒルクライム）＋ミニ標高グラフ
- M6 Googleマップ連携: `https://www.google.com/maps/dir/?api=1&origin=..&destination=..&travelmode=bicycling`
  - 「往復ルート」も選べる（origin=現在地, destination=現在地, waypoints=目的地）
- M7 フィルタ/並び替え: 高低差（フラット/ゆる/ヒル）、カテゴリ、距離順・ランダム順
- M8 PWA: manifest、Service Worker、ホーム画面追加、オフライン時はアプリシェル表示
- M9 モバイルファースト（片手操作、親指ゾーンにCTA）

### SHOULD（v1でできれば）
- S1 「ガチャ」ボタン: 迷ったらランダムで1件を演出付きで提案
- S2 習慣化: 「走った！」記録 → 連続日数ストリーク、今週の走行回数、訪れた場所スタンプ（localStorage）
- S3 行ったことのある場所に「訪問済み」バッジ、未訪問を優先表示するオプション
- S4 お気に入り

### WON'T（v1ではやらない）
- アカウント/サーバー、実走行のGPSトラッキング、SNS共有、天気（v2候補）

## 5. 非機能要件
- 技術: Vite + React + TypeScript + vite-plugin-pwa。サーバーレス（静的ホスティング可）。
- API キーは任意。キー無しで完全に動くこと。
- 外部API は並列数・件数を絞る（Open-Meteo は1リクエスト最大100点なので候補をまとめてバッチ）。結果はセッション内キャッシュ。
- 初回表示 3秒以内に「何か」を見せる（スケルトン → 段階的に写真・標高が埋まる）。
- アクセシビリティ: コントラスト、タップ領域44px以上、prefers-reduced-motion 対応。
- テスト: 距離計算・標高ラベル判定・URL生成・Provider フォールバックはユニットテスト（Vitest）。

## 6. 成功指標（将来計測）
- アプリ起動 → Googleマップ遷移までの中央値時間 < 20秒
- 週あたりの「走った！」記録回数

## 7. スマホアプリ化の方針
- Phase 1: PWA（ホーム画面追加でアプリ同等）← 今回
- Phase 2: Capacitor でラップし iOS/Android ストア配布（要: Apple Developer / Google Play 登録、署名、アイコン）
